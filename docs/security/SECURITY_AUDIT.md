# Auditoría de seguridad

Fecha: 30 de julio de 2026.

## 1. Alcance y método

Revisión estática y dinámica local de frontend, backend, configuración, lockfiles, Docker, Git,
historial accesible, PWA, IndexedDB, endpoints, tests y documentación. Se ejecutaron las suites
locales finales, comprobaciones npm/NuGet, PostgreSQL real, escaneos de imagen y búsquedas
redactadas de secretos. No se atacó ningún sistema externo ni se usaron datos reales.

Estados:

- **Verificado localmente:** existe en código y pasó la prueba o herramienta local indicada; no
  equivale a CI remoto ni a validación de producción.
- **Verificado estáticamente:** comprobado por lectura o herramienta local de solo lectura.
- **Pendiente de infraestructura:** necesita dominio, proveedor o credenciales.
- **Abierto:** no resuelto.
- **N/A:** no aplica a la arquitectura actual.

No se afirma que MIGA sea “segura”, conforme al RGPD ni ASVS L2. La checklist detallada está en
[OWASP_ASVS_CHECKLIST.md](OWASP_ASVS_CHECKLIST.md).

## 2. Arquitectura detectada

- React 19/TypeScript/Vite PWA.
- ASP.NET Core/.NET 10, Identity, cookies y antiforgery.
- EF Core/Npgsql/PostgreSQL con esquemas `auth`, `app` y `audit`.
- Workspaces demo/registrado y snapshots JSON.
- IndexedDB aislado por identidad.
- Blobs de PDF/vídeo/audio/imagen exclusivamente locales.
- SMTP opcional, YouTube Data API/IFrame API y Data Protection persistido en PostgreSQL.
- GitHub Actions, Dependabot, npm/NuGet lockfiles y PostgreSQL fijado por digest.

## 4. Secretos e historial

La revisión inicial por patrones abarcó 241 archivos de texto y los diffs entonces accesibles.
Después, Gitleaks `8.30.1`, descargado desde su release oficial y verificado con SHA-256, ejecutó
la comprobación final:

- `gitleaks dir`: espejo de 403 archivos y 5,08 MB (1,98 MB analizados por reglas), cero
  filtraciones detectadas;
- `gitleaks git`: 63 commits y aproximadamente 2,30 MB analizados, cero filtraciones detectadas.

La revisión manual complementaria:

- no encontró patrones fuertes de clave privada, PAT GitHub, AWS, Google, Slack, Stripe o JWT
  completos;
- sí confirmó una antigua contraseña PostgreSQL de desarrollo repetida en configuración/documentos;
- el valor fue eliminado del árbol actual y sustituido por un marcador en las bitácoras;
- no se reescribió Git.

El valor histórico tenía entropía baja y Gitleaks no lo clasificó como secreto; por eso el resultado
automático no elimina la obligación de rotarlo si se reutilizó. El mismo escaneo está configurado en
CI, pero el workflow aún no se ha ejecutado. No se inspeccionaron objetos Git
inaccesibles/dangling, forks ni cachés externos.

## 5. Dependencias

Resultado observado sobre los lockfiles finales:

```text
root, auditoría completa:       0 vulnerabilidades (exit 0)
frontend, auditoría completa:   0 vulnerabilidades (exit 0)
root, --omit=dev:               0 vulnerabilidades (exit 0)
frontend, --omit=dev:           0 vulnerabilidades (exit 0)
```

`concurrently`, que no se usaba, fue retirado del manifiesto raíz y el lockfile frontend resolvió
versiones corregidas de sus transitivas. Este resultado es puntual a la fecha de la auditoría y no
sustituye Dependabot ni la comprobación recurrente en CI.

Los lockfiles npm v3 tienen integridades y no resuelven dependencias desde Git. Los proyectos .NET
usan lockfiles. La auditoría NuGet final recorrió los siete proyectos y no informó paquetes
vulnerables; el control se repite en CI.

Trivy `0.72.0`, con su base de vulnerabilidades del 30 de julio de 2026, encontró en la imagen base
fijada 15 vulnerabilidades corregibles dentro de `/usr/local/bin/gosu`: una Critical
(`CVE-2025-68121`) y catorce High de la biblioteca estándar Go 1.24.6; no encontró vulnerabilidades
del sistema Alpine. No se añadió una excepción. `docker/postgres/Dockerfile` elimina ese binario en
una fase sin red y fija `USER postgres`; CI construye la derivada, comprueba ambas propiedades,
inicializa un volumen nuevo con ella y escanea la imagen final. El build local confirmó usuario no
root, ausencia de `gosu`, inicialización y persistencia tras recrear el contenedor con el mismo
volumen temporal.

El 30 de julio de 2026, el rescan real de `miga-postgres-security-audit:local` con Trivy `0.72.0` y
su base actual terminó con exit `0`: Alpine 3.23.5, 45 paquetes del sistema, cero High/Critical y
ningún fichero específico de lenguaje. La imagen conservó PostgreSQL 17.10, `Config.User=postgres`,
UID 70 y `gosu` ausente. La ejecución del workflow en GitHub continúa pendiente.

El job de imagen no ejecuta `trivy-action` ni `setup-trivy`: descarga el binario oficial `0.72.0` y
comprueba el SHA-256 publicado. Esta decisión reduce la superficie tras el
[incidente oficial del ecosistema Trivy de marzo de 2026](https://github.com/aquasecurity/trivy/security/advisories/GHSA-69fq-xp46-6x23);
la versión y su checksum requieren mantenimiento deliberado.

## 7. Verificación pendiente antes de producción

1. workflow GitHub completo verde —incluidos CodeQL, Gitleaks, Trivy y PostgreSQL— y checks
   requeridos en `main`;
2. candidato SQL revisado por una persona y upgrade ensayado desde la versión productiva anterior;
3. roles migrador/runtime, privilegios y grants mínimos verificados en PostgreSQL de producción;
4. dominio HTTPS/TLS real, headers, CORS, hosts y proxy;
5. backup PostgreSQL y keyring restaurados en entorno aislado, con DR/RPO/RTO ensayados;
6. sink/SIEM externo, alertas, acceso y retención de logs/eventos;
7. carga y despliegue multiinstancia, incluido rate limiter, caché y cleanup coordinados;
8. SMTP sandbox y producción, sin tokens en logs y con métricas/entrega operativa;
9. revisión jurídica y política de retención;
10. decisión explícita para los blobs local-only.

Hasta completar esos puntos, MIGA no está preparada para producción.
